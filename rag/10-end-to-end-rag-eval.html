“RAG 回答错了”不是诊断。
你必须知道是哪一层错了。

一个最终错误可能来自：没召回证据、召回了却在 packing 时丢掉、证据正确但模型过度推断、答案正确但 citation 指错位置。最后一课把整条链放进同一个 Trace，用分层指标 + Failure Taxonomy + Regression Gate把 RAG 从 Demo 收口成可评估系统。

3

四层 Failure Taxonomy

以后线上失败样本也按这套分类进入 eval set。
Retrieval

required evidence 没进入候选；query plan、parser、chunk、embedding、BM25、ANN 都可能是根因。

Evidence

证据已召回，但 dedup、budget、source cap、context packing 把关键 evidence 丢了。

Generation

正确证据已提供，但模型仍 hallucinate、过度推断、漏答或违反 task contract。

Citation

claim 本身可能正确，但 citation 缺失、错 id、错页或证据并不 entail 该 claim。

这四类并不互斥，但 root-cause 分析要优先找最早的失败层。
4

Answer correctness ≠ Groundedness

模型可能靠预训练知识“猜对”，但这仍然不是一个合格的 RAG 答案。
答案证据评价
结论正确Evidence 直接支持✅ correct + grounded
结论碰巧正确Evidence 没提到⚠️ correct but ungrounded
结论错误Evidence 正确❌ generation failure
拒答语料确实无答案✅ calibrated abstention
高质量 RAG 不只是答对。还要能证明这次答案来自你提供的 evidence，而不是模型自己的记忆或猜测。
5

Citation 要拆成 correctness 和 completeness

“有引用”本身不是指标。
Citation correctness

模型给出的 citation 中，有多少真的支持对应 claim？

valid_citations / all_citations
Citation completeness

应该有证据的重要 claim 中，有多少真的挂了 citation？

cited_required_claims / required_claims
一个回答可以 correctness=1.0、completeness=0.33。因为它只给了一条完全正确的引用，但另外两条重要事实完全没引。
6

Eval 样本最好携带“预期证据”和“预期 claim”

这样 Failure Classifier 才能知道问题出在哪。
RAGEvalCase(
    id="compare-A-B-01",
    required_evidence_ids={"a-method", "b-method", "a-ec-result"},
    required_claim_ids={"method-a", "method-b", "ec-mechanism"},
    tags={"comparison", "critical-citation"},
)

trace = RAGTrace(
    case_id="compare-A-B-01",
    retrieved_ids=[...],
    packed_evidence_ids=[...],
    claims=[...],
)
这不是要求每个开放问题都有唯一标准答案，而是把必须覆盖的关键事实和证据变成可检查 contract。

RAG 03 · Research Assistant v2.3

Embedding 不是“把文字压成数字”。
它是在构造一个可比较的语义空间。

Chunking 决定检索系统有哪些“证据单元”；Embedding 决定这些单元在向量空间里的相对位置。真正要理解的不是 1536 维这个数字，而是：什么叫相似、用哪种距离、模型版本为什么不能乱混、语义相近为什么不等于事实正确。

3

Cosine、Dot、L2 到底差在哪？

它们不是可以随便互换的三个名字。
Cosine

比较夹角，关注方向。常见于已归一化或方向语义更重要的 embedding。

Dot Product

方向和长度都会影响结果。若向量已单位归一化，它与 cosine 排序可等价。

L2 Distance

欧氏距离，越小越近。是否合适取决于模型/索引约定。

cos(a,b) = (a · b) / (||a|| ||b||)
dot(a,b) = Σ aᵢbᵢ
L2(a,b) = √Σ(aᵢ-bᵢ)²
工程规则：Embedding provider 给出的推荐 metric 要和 Vector Index 的 metric 保持一致。不要模型用 cosine 语义，索引却不经思考改成另一个距离。

危险做法：索引里的 chunk 是旧模型生成的，部署后 query 改成新 embedding model，却不重建索引。两边向量即使维度恰好一样，也不代表语义空间兼容。
5

Embedding 相似 ≠ 事实支持

Semantic retrieval 找的是“像”，不是“真”。
Query

“无序增强时 Ec 会降低吗？”

高相似 Chunk

“Earlier work discussed disorder-dependent coercive field.”

主题很像，但不一定真的回答“降低”。

所以 retrieval 后还要：rerank、evidence checking、citation、generation eval。Vector similarity 只是候选生成信号。
6

Embedding 输入也要设计

你 embed 的字符串是什么，会改变空间里的位置。
裸正文
Near depinning, velocity follows...

可能丢章节语义。

带结构上下文
[Section: Domain-wall depinning]
[Subsection: Finite-size scaling]
Near depinning, velocity follows...

更容易让 embedding 认识这个片段的主题。

这正是 RAG 02 为什么要把 heading path 带入 Chunk。Embedding 层不应该重新猜文档结构。

批量不是无限大。还要受 provider request limit、token limit、timeout、rate limit、失败重试和内存约束。批次大小应观测后调，不要把“100”背成常数。
8

Embedding 也要版本化

它其实是索引数据的一部分。
EmbeddingRecord(
    chunk_id="doc42:sec3:block5:v2",
    model="embedding-model-v3",
    dimension=1024,
    normalized=True,
    vector=[...],
)
为什么重要：换模型、换预处理、换 normalize 策略，都可能需要重新 embedding。没有 metadata，你甚至不知道线上这批向量是谁生成的。

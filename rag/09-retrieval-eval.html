RAG 09 · Research Assistant v2.9

先把 LLM 拿掉。
只问一件事：检索到底把对的证据找回来了吗？

最终回答错时，如果你直接盯着生成结果，很难知道是 Retriever 没找到、Reranker 排错，还是模型拿到正确证据仍然答错。Retrieval Eval 的价值就是把生成模型隔离出去，用一组有相关性标注的 query → chunk/document直接测检索链。

Golden relevance set：你必须先知道“哪些结果算相关”

Eval 不是拿一个 query 看结果顺不顺眼。
RetrievalEvalCase(
    id="ec-disorder-01",
    query="无序增强后 Ec 为什么下降？",
    relevance={
        "chunk-results-7": 3,   # 直接回答
        "chunk-mechanism-4": 2, # 强支持
        "chunk-background-2": 1,# 部分相关

Precision / Recall / Hit Rate：三个最容易混的指标

它们回答不同问题。
Precision@K

top-k 里，有多少比例是真的相关？

relevant_in_top_k / K
Recall@K

所有应找到的相关证据里，我找回了多少？

relevant_in_top_k / all_relevant
Hit Rate@K

top-k 里只要至少有一个相关结果，就记 1。

1 if any relevant else 0
为什么都要看

一个系统可以 Hit@5=100%，但每次只勉强命中一条弱相关证据；它并不等于 evidence coverage 很好。

5

MRR：第一条相关结果有多早出现？

对“用户只看最前面几条”的场景特别直观。
排名：
#1 irrelevant
#2 irrelevant
#3 relevant  ← 第一条相关

Reciprocal Rank = 1 / 3
MRR 的局限：它只关心第一条相关结果。后面第二、第三条高价值证据排得怎样，它不在乎。所以多证据 RAG 不能只看 MRR。
6

直接答案排在前面，应该比弱相关背景排在前面得分更高。

背景

DCG 会给高 relevance 更大 gain，同时对靠后的排名做 discount；再除以理想排序的 IDCG，就得到 0–1 范围的 nDCG。

所以 nDCG 特别适合 graded relevance。但前提是你的标注标准一致，否则“3 分”和“2 分”本身就很噪。
7

Eval Set 不能只有“正常自然语言问题”

前八课遇到的所有边界，都应该变成 slice。
Semantic

同义表达、机制问答。

Identifier

DOI、错误码、型号、符号。

Comparison

多论文、多子问题。

Long / ambiguous

指代、长 query、上下文依赖。

Table / figure

答案藏在表格或图注。

Negative

语料里根本没有答案，系统不该硬召回“看起来像”的证据。

整体平均 0.88 很可能掩盖问题。如果 identifier slice Recall@5 只有 0.42，你应该回头查 tokenizer/BM25，而不是继续调 dense embedding。
8

对比实验要固定 Query Set，而不是“我随手试了几个”

Chunking、Embedding、ANN、Hybrid、Rerank 都能用同一套离线 eval 比较。

什么时候 Retrieval Eval 仍然不够？

当证据已经找对，但最终回答还是错。

系统 Recall@5=1.0，正确证据都在 top-5，但最终回答仍然编了一个证据中不存在的结论。首先说明什么？

面试验收：① Precision@K / Recall@K / Hit Rate 区别？② MRR 在看什么，局限是什么？③ nDCG 为什么适合 graded relevance？④ 为什么 retrieval eval 要脱离 LLM？⑤ 什么是 hard negative / negative query？⑥ 为什么要做 slice analysis？⑦ 怎么比较两种 chunk/embedding/ANN 配置？⑧ Recall 高但答案错，下一步查哪里？

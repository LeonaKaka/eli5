Agent 会发 tool call，
离“真的能干活”还差一个 Tool Runtime。

工程问题：用户说“查资料，分析数据，给我结果文件”。真正的 Agent 必须把网页内容、文件、生成代码、进程和最终 artifact 放进一个可控运行环境。这里做一条完整的 Browser → Workspace → Python → Artifact 闭环。

如果中间没有 Runtime，你最终往往会写成：模型给一段 Python → 主进程直接 `exec()`。这同时丢掉了 cwd、文件生命周期、timeout、环境变量、artifact 归属和安全边界。

2

一个 Run，一个 workspace

run-42/
├── inputs/       # 浏览器/上传文件/外部数据的落盘副本
├── work/         # Agent 生成的中间代码与临时文件
└── artifacts/    # 最终要交给用户/后续步骤的产物

模型不直接拿主机任意路径。公开 filesystem tool 先通过 `AgentWorkspace.resolve()`，拒绝 absolute path 和 `../` escape；写入只允许固定根目录。

Artifact 和 prompt 不是一回事。一个 50 MB CSV 或 PNG 不应该为了“给 Agent 看见”直接塞进 context。Runtime 可以只把 artifact metadata / path /摘要交回模型，真正文件继续留在 workspace。

Browser：先限制“去哪”，再讨论“网页说了什么”
BrowserPolicy(
  allowed_schemes={"http", "https"},
  allowed_hosts={"papers.example.test"},
)

await browser.read(url)
真实 adapter 使用 Playwright；课程测试用 fixture browser，这样 CI 不依赖公网或 Chromium。Runtime 先做 URL scope，再把页面 title/body 保存到 `inputs/source.json`。下一章会进一步讨论：即便 URL 合法，页面文本本身也仍是不可信输入。
5
Shell：argv + shell=False，只是第一道门
较好的工程 guardrail
run([
  "wc", "-w", "inputs/data.txt"
])

cwd = workspace
shell = False
env = minimal
timeout = 5s
不要这样
cmd = model_output
subprocess.run(
  cmd,
  shell=True,
)

# 模型输出直接获得 shell 语法权力
课程版还用 command allowlist，并拒绝 absolute / `..` path argument。但这仍然不是安全沙箱：一个本来就很强的允许命令，或者一个可执行程序里的漏洞，都可能突破应用层规则。
6
Python：独立进程 ≠ 安全沙箱
python -I work/generated.py

cwd = run workspace
env = {PATH, PYTHONIOENCODING}
timeout = 8s
stdout/stderr bounded
把生成代码放到独立 interpreter 里很有价值：它不会污染 FastAPI/Worker 主进程的 Python state，也有明确 timeout、stdout/stderr 和 artifact 文件。但同一个 OS 用户启动的 Python，理论上仍可以读取主机文件、访问网络、fork 进程。
所以课程源码里直接写着：not a security sandbox。真正的安全边界要进一步限制 filesystem mount、network egress、process capability、CPU/RAM/time，并假设代码可能是恶意的。这正是 A3。

v6.3 真实代码结构
AgentToolRuntime
├── browser: BrowserAdapter
├── workspace: AgentWorkspace
├── shell: ShellRunner
├── python: PythonRunner
└── artifacts: ArtifactRegistry

run_research_artifact_demo()
  Browser.read(url)
  → inputs/source.json
  → generate summarize_source.py
  → PythonRunner
  → artifacts/summary.json
这里最重要的不是这些 class 名，而是 ownership：Run 拥有 workspace；Runtime 拥有工具 policy；模型只提出调用；artifact 是显式产物；主 API 进程不应该随便执行模型代码。
9
故意失败：为什么这些 guardrail 还不够？
已经防住
公开文件 API 的 `../`、absolute path；未允许 shell command；shell=True；无 timeout；整个 host env 自动继承。
仍未根治
Python 自己调用 `open('/etc/...')`；网络 exfiltration；fork bomb；内核/浏览器漏洞；网页里的 indirect prompt injection；合法工具被模型以错误目的调用。
这就是为什么下一章不是继续加更多 Tool API，而是直接做 Agent Security。

面试验收
把模型生成 Python 放进 `subprocess.run(..., timeout=8)` 后，能否称为安全沙箱？
能讲清这几题：① 为什么 tool call 和 tool runtime 是两层？② workspace 和 artifact registry 分别解决什么？③ 为什么 `shell=False` 重要但不充分？④ 为什么 Python subprocess 仍不是安全 sandbox？⑤ Browser URL allowlist 和网页内容可信度为什么是两回事？⑥ 为什么大 artifact 不应该直接塞 context？⑦ API process 与 code-execution worker 为什么最好分开？

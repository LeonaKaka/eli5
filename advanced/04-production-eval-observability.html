A4 · Research Assistant v6.5

成功率从 92% 掉到 78%。
别先改 prompt，先找哪一层坏了。

线上 Agent 的最终答案只是最后一个结果。真正诊断要把同一个 Run 拆回 model / retrieval / tool / retry / runtime，再把 trace、metrics 和 quality eval 对齐。

1

只看 final success，几乎无法调系统

92% success
→
deploy / traffic change
→
78% success
→
???

可能是搜索 API timeout，也可能 retrieval 还返回 200 但证据变差；可能模型没坏只是价格翻倍；也可能答案质量没变但 Worker 排队从 100 ms 变成 10 s。它们需要完全不同的修法。

2

四种信号各回答不同问题

Metrics什么时候、多少 Run 变坏？ success / latency / cost / error rate
Trace一个 Run 的因果路径在哪层变坏？ model → retrieval → tool → retry
Eval即使所有请求都 200，结果质量到底好不好？ evidence / answer / trajectory
Audit谁批准了什么高风险动作？用于安全/合规，不是质量评分。
同一个 run_id 可以把四种数据关联起来，但不要把它们做成一张万能日志表。
3

Trace 要能看到 Agent 的“里面”

invoke_agent 530 ms
retrieve 90 ms · docs=6
chat 320 ms · 1550 tokens
execute_tool 80 ms · search_papers

当前 OpenTelemetry GenAI 语义已经覆盖 Agent、模型与 tool execution 一类操作。课程代码不绑定某个观测平台，只保留相同的层次结构与低敏属性，后面可以导出到 OpenTelemetry / LangSmith / 其他 tracing backend。

4

Interactive · Incident Console

同样是“用户说变差了”，切换事故类型，看应该追哪种信号。
5
Failure clustering：不要让 1000 条错误看起来像 1000 个问题
run-201  → tool:search_timeout
run-202  → tool:search_timeout
run-203  → quality:missing_evidence
run-204  → runtime:worker_lease_expired
...
先把失败归一成稳定 cluster，再看当前批次相对 baseline 哪个 cluster 暴涨。v6.5 的 `ProductionRunAnalyzer` 还按 layer 计算“有多少 Run 至少在这一层失败”，避免同一 Run 重试 5 次就被错误地算成 5 个用户失败。
6
所有 span 都绿色，质量仍然可能坏掉
Operationally healthy
retrieve  200
chat      200
tool      200
latency   normal
Quality regression
evidence coverage  ↓
answer score       .95 → .72
citations          wrong
这就是为什么 observability 不能替代 eval。线上 trace 告诉你“系统做了什么”；golden case / human review / calibrated judge 才能告诉你“做得对不对”。
7
Release gate：Offline regression + Online sampled eval
Golden Set
→
candidate model/prompt/tool
→
quality + trajectory gate
→
small rollout
→
sampled online eval
CI 里的 golden regression 防已知能力退化；线上 sampled eval 发现真实流量的新 failure mode。LLM judge 可以扩大规模，但它本身也必须被人类样本校准，不能把“另一个模型给了 0.9”当真值。
8
Observability 不是把所有 prompt 全存下来
默认记录run/trace/span id、layer、operation、latency、status、error type、model/tool name、token/cost、低敏计数。
谨慎 opt-in完整 prompt、completion、tool arguments/results、retrieved documents——它们可能含 PII、secret、客户数据和攻击内容。
始终分开Security audit 记录批准/授权事实；debug trace 记录执行路径；quality eval 记录评分与标签。

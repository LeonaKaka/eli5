Agent 01 · Research Assistant v3.1

Tool Calling 只是“模型提出一个动作”。
Agent 是“执行后再看结果，继续决定下一步”。

前面 LLM 07 已经学过 Tool Calling：模型可以返回 search_papers(...)。但如果应用执行完就结束，那只是一次工具调用。Agent 的关键变化是：Tool Result 会成为新的 Observation，系统再进入下一轮 Decide。

1

先看一个真实问题：检索一次根本不够

用户问“找最相关论文并比较方法”，你事先不知道要调用几次工具。

下一步动作由当前状态和新 observation 决定。

分界点不是“有没有 Tool”。而是执行结果是否会回到决策循环，并影响下一步动作。

注意：模型不是在“一次响应里偷偷执行多步”。应用每一步都要显式拿到 decision、验证/执行 action、保存 observation，再调用下一轮 decision。
3

Agent Loop 最少需要四种东西

少一个，系统就很难调试。
State

目标、已有 observation、历史动作、预算、状态。

Decision

下一步是调用哪个 Tool，还是给最终答案。

Action Executor

真正执行动作；权限和参数校验仍由应用负责。

Trace

每一步为什么做、做了什么、得到了什么。

LLM 可以参与 Decision，但它不应该拥有整个控制面。ToolExecutor、权限、budget、stop condition 都应该留在应用侧。
4

Decision 最好是结构化对象，不是一段“思维文本”

你真正需要执行的是动作，而不是依赖模型写一段自然语言计划。
AgentDecision(
    kind="tool",
    tool_call=ToolCall(
        id="call_2",
        name="fetch_paper",
        arguments={"paper_id": "paper_17"},
    ),
)

# 或
AgentDecision(
    kind="final",
    final_answer="现有证据足够……",
)
价值：模型输出可以验证；应用知道这是 TOOL 还是 FINAL；测试也能断言“第 2 步应该调用 fetch_paper”，而不是比较一整段自由文本。
5

Observation 是 Tool Result，但不是原样无限堆历史

观察结果也需要结构、裁剪和来源。
Observation(
    step=2,
    source="fetch_paper",
    ok=True,
    summary="Methods and Results extracted",
    payload={...},
)
大 Tool Output 要谨慎。把 5MB HTML、完整 PDF 或巨型 JSON 每轮重复塞回模型，会迅速把 context、成本和注意力吃光。Agent state 可以保存完整数据，给模型的 observation 只保留决策真正需要的部分。
6

Agent 自主性到底在哪里？

不是“模型能干任何事”。
应用定义
Tool Space
→
模型选择
下一动作
→
应用验证
Permission
→
Executor
Act

Agent 的“自主”更准确地说，是：在应用给定的动作空间和约束内，根据当前状态动态选择下一步。

这比“把 shell、浏览器、数据库管理员权限全给模型”安全得多，也更可测试。
7

什么时候根本不该用 Agent？

动态循环不是越多越高级。
任务更合适
输入固定 → 结构化抽取一次模型调用 + Schema
固定 Search → Summarize普通 workflow
下一步取决于搜索结果，步数不确定Agent loop
高风险审批流程显式 workflow + human checkpoint，不能全自动
Agent 带来的是动态决策能力，也带来更大的状态空间。如果流程本来就是固定的，用 Agent 只会增加不可预测性、成本和测试难度。
8

Trajectory 比最终答案更重要

Agent 的失败常常发生在中间动作。
step 1  decide search_papers      ✅
step 2  observe 3 papers          ✅
step 3  decide delete_cache       ❌ unnecessary action
step 4  decide fetch paper        ✅
step 5  final answer              ✅
最终答案碰巧对，也不代表 trajectory 合格。以后 Agent Eval 会单独测 tool-choice accuracy、unnecessary-step rate、loop efficiency 和危险动作。

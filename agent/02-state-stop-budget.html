Agent 02 · Research Assistant v3.2

会循环之后，第一件事不是“让它更聪明”。
是确保它知道什么时候必须停。

Agent 最危险的 bug 往往不是一次答错，而是反复做同一件事、不断失败重试、持续烧 token / API / side effect。因此生产 Agent 必须有应用侧 hard limits：State Machine、Run Budget、Stop Reason 和 Loop Guard。

1

为什么“让模型自己判断该停了”不够？

因为模型的 stop decision 本身也可能失败。
典型事故：
search_papers("rare topic")
→ 没结果
→ 模型：再搜一次也许有
→ 没结果
→ 再搜
→ 再搜
→ 再搜……

如果唯一停止条件是“模型什么时候想起来说 final”，系统没有可信的硬边界。

安全设计：模型可以主动完成，但应用必须拥有最终 veto：超过 step/tool/failure/repetition 等已配置 budget 时，LoopGuard 可以强制停止。

Stop Reason 必须是数据，不是一句日志

否则后面无法统计为什么 Agent 停了。
StopReason.FINAL_ANSWER
StopReason.MAX_STEPS
StopReason.TOOL_BUDGET
StopReason.FAILURE_BUDGET
StopReason.REPEATED_ACTION

StopReason.CANCELLED
v3.2 已真正执行：`MAX_STEPS / TOOL_BUDGET / FAILURE_BUDGET / REPEATED_ACTION`；`NO_PROGRESS / CANCELLED` 先作为显式状态语义保留，后续 Planning / durable run 会继续实现。如果线上 18% run 都因为 `REPEATED_ACTION` 结束，你就有了可统计的故障信号。
5

Budget 不只是 max_steps

不同资源应该有不同硬限制。
Budget保护什么v3.2
max_steps总循环次数，防无限运行✅
max_tool_calls外部 API / 浏览器 / DB 压力✅
max_failures避免坏依赖持续失败✅
max_same_action拦机械重复动作✅
token / cost budget模型成本后续
wall-clock deadline用户等待和 worker 占用后续
side-effect budget写操作/发送/删除风险后续 Guardrails
预算应该按 run 配置。“查一个定义”和“做 30 分钟科研调研”不该共享同一个 max_steps。
6

Action Fingerprint：怎么判断“又做了一样的事”？

不能只比较 Tool 名。
search_papers(query="depinning")
search_papers(query="depinning")
# same fingerprint

search_papers(query="depinning", year_from=2025)
# different fingerprint
v3.2 的 fingerprint 由 `tool_name + canonicalized arguments` 组成；参数 key 顺序不同也会得到相同 fingerprint。后面还能再加入 observation hash / progress signal。
7

No Progress 比 Repeated Action 更难

动作不同，也可能一直原地踏步。
search_web(...)
→ no evidence
search_papers(...)
→ no evidence
search_crossref(...)
→ no evidence
search_web(new wording)
→ no evidence

动作 fingerprint 都不同，但 objective state 一直没增加有效 evidence。

这一层 v3.2 还没有假装实现。03 Planning 会开始给“progress”结构化定义，例如未完成 subgoal、有效 evidence 数、状态差异；再把 `NO_PROGRESS` 从枚举语义变成真正 guard。
8

Stop 之后应该发生什么？

强制停止不等于给用户一个空白错误页。
Graceful stop

说明已做到哪里、为什么停、已有部分结果、下一步需要什么。

Hard failure

保存 trace/checkpoint，返回明确错误类别，允许用户重试或恢复。

例如 `MAX_STEPS` 可以返回“已找到 4 篇论文但未完成比较”；这比继续烧 50 步，或直接丢失全部中间成果都更合理。
9

Research Assistant v3.2：LoopGuard + RunBudget

控制逻辑从 prompt 里搬到应用代码。
budget = RunBudget(
    max_steps=8,
    max_tool_calls=6,
    max_failures=2,
    max_same_action=2,
)

result = await AgentLoop(
    decision_maker=policy,
    tool_executor=executor,
    guard=LoopGuard(budget),
).run(objective)
原则：Prompt 可以告诉模型“避免重复”，但 hard guard 不能只存在 prompt 里。应用代码必须能独立终止 run；被 Guard 拦下的 proposed action 也会先写入 trajectory，方便审计。

01 · Research Assistant v6.1

MCP 不是“Agent 的 USB”。
先搞清楚谁在控制什么。

我们的 Agent 已经会 Tool Calling，但工具仍然跟应用代码绑在一起。MCP 的价值是把能力提供者和模型宿主应用拆开，并用统一协议发现/调用。第一课只做一件事：建立不会混乱的 Host / Client / Server / Primitive 心智模型。

1

先看真实工程问题

Research Assistant 现在想接：

paper search
filesystem
GitHub
SQL database
lab instrument
browser

如果每个能力都这样：

app/search_tool.py
app/github_tool.py
app/sql_tool.py
app/filesystem_tool.py
...

→ 每个 Host 都重新做 schema / discovery / transport / errors / lifecycle glue

MCP 的目标不是替你做业务逻辑，而是让能力提供者用统一接口告诉 Host：“我能做什么、怎么调用、有什么上下文/模板”。

2

Host → Client → Server，三层不要揉成一团

Host真正的 AI 应用。拥有 LLM、LangGraph、conversation、tenant、permission、approval、UI。
→
MCP ClientHost 里负责讲 MCP 的连接实例。discover/list/call/read/get。
→
MCP Server独立能力提供者。可以本地进程，也可以远程服务。
关键：模型通常不“直接连接 MCP server”。Host 创建 client，Host 决定把哪些能力交给模型。
3

三种 primitive 的区别首先是“控制权”

Primitive
典型控制者
你应该问的问题
例子
Tool
Model
模型是否应该决定何时执行这个 capability？
search / query / write / create
Resource
Application
这是 Host 应该按 URI 选择并装入 context 的数据吗？
file / schema / paper record / config
Prompt
User
这是用户明确选择的可复用 workflow/template 吗？
compare papers / review draft

这是官方 MCP 长期采用的核心分工：Tools 偏 model-controlled，Resources 偏 application-controlled，Prompts 偏 user-controlled。真正实现可以有 UI/策略变化，但用这个控制层次判断最不容易设计错。

5
为什么“读 paper”可能同时出现 Tool 和 Resource？
search_papers("domain wall")
→ Tool
→ 模型不知道 paper id，主动搜索

research://paper/rfim-domain-wall
→ Resource
→ Host 已经知道准确地址，读取指定 context
它们不是按“底层都是数据库 SELECT”分类，而是按上层控制语义分类。同一个 backend 完全可以同时支撑 Tool 和 Resource。
6
MCP 和 LangGraph 不重叠
MCP
能力发现、调用、资源、模板、transport/protocol。
LangGraph
Agent state、control flow、checkpoint、interrupt/resume。
FastAPI / App
身份、tenant、业务 command、HTTP 产品 API。
错误想法
“接了 MCP，我就不需要权限、approval、RunStore、Agent runtime。”
7
Capability discovery 不是 capability authorization
MCP Server advertises:

- read_file
- write_file
- delete_file
- run_shell

Host policy may expose to this Agent:

✅ read_file
✅ write_file(workspace only)
❌ delete_file
❌ run_shell
这是后面 MCP Security 的核心前提：server 能做什么和当前模型被允许做什么必须是两层。
8
2026 的 MCP 还发生了一个重要变化
最新 2026-07-28 协议把现代 HTTP 核心改成 stateless：不再要求旧式 initialize/session id；请求可以带上协议/客户端元信息独立到达任意 replica。Server discovery 也有新的 `server/discover`。这对后面第 03 课的远程 MCP 扩容很关键。
因此网上很多“每个 MCP client 必须维持一个 stateful HTTP session”的旧文章，现在只能代表旧协议时代。

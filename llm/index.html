LLM Application Engineering · 10 课

不是“会调模型 API”。
是把不确定的模型接成可靠产品。

这条能力线只解决模型本身：怎么请求、怎么给上下文、怎么控制生成、怎么拿结构化结果、怎么流式展示、怎么调用工具、怎么控制成本和质量。RAG 检索细节与复杂 Agent 编排留到后面的独立能力线。

这 10 课为什么这样分？

顺序对应一个 LLM 功能从“第一次请求”走到“能上线”的真实演化。
1
先能调用

模型 API、认证、请求与响应。

2
再能对话

Messages、Instructions、conversation state。

3
学会装上下文

Token budget、context window、caching。

4
控制行为

生成参数、reasoning、输出预算。

5
改善交互

Streaming、取消和 partial output。

6
让程序消费结果

Structured Output + validation。

7
让模型请求动作

Function calling；动作仍由应用执行。

8
不只看文字

Image / PDF / audio / files。

9
把成本和稳定性纳入设计

Routing、fallback、cache、rate limit。

10
证明真的变好了

Evals、error analysis、prompt version、production safety。

学完后简历上应该能说什么？

不是“熟悉 OpenAI API”，而是可以解释工程 trade-off。
目标表达：“设计 provider-agnostic LLM client，支持 conversation context、streaming、schema-constrained output 与 function calling；记录 token/cached-token、latency、cost 和错误类型，并通过 eval set 做 prompt/model regression。”
必须能实现

请求模型、管理 history、token budget、流式输出、结构化返回、tool call、timeout/retry、usage 记录。

必须能解释

stateful/stateless、context 为什么会爆、cache 是什么、reasoning 与输出长度的区别、质量/成本/延迟如何取舍。

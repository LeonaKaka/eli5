JSON：只是“双方约定的数据文本格式”

Python dict 和 JSON 长得像，但不是同一个东西。
Python 对象
payload = {
  "query": "RAG",
  "top_k": 5,
}
serialize →
网络里的 JSON 文本
{"query":"RAG","top_k":5}
→ parse
对方程序对象

JavaScript object、Go struct、Java class…语言可以完全不同。

import json

payload = {"query": "RAG", "top_k": 5}

text = json.dumps(payload)   # Python dict → JSON str
data = json.loads(text)      # JSON str → Python object

哪个说法更准确？

5

Status Code：服务端先给你一个“结果类别”

不要只会看 200。Agent 调外部服务时，状态码直接决定你下一步该怎么办。
2xx请求成功

继续解析结果。

4xx请求/权限/频率问题

通常先检查自己发了什么。

5xx服务端失败

可能是临时故障，可考虑有限重试。

状态AI 工程里常见含义第一反应
400JSON/schema/参数错误别重试同一个坏请求，先修数据
401 / 403认证或权限错误检查 key / scope / 账号权限
404资源/endpoint 不存在检查 URL / ID
429rate limit / quota读取限制信息，等待后有限重试
500 / 503供应商服务异常记录日志，考虑 backoff / fallback
第 06 课会专门把 retry、backoff、fallback 做成完整 Failure Engineering。这里先记住：不是所有失败都应该重试。

第一次用 httpx：别让 SDK 遮住网络基础

先写最普通的 client，再去用 OpenAI / Anthropic SDK，你会知道框架替你做了什么。
import httpx

payload = {
    "query": "RAG evaluation",
    "top_k": 5,
}

response = httpx.post(
    "https://api.example.com/v1/search",
    json=payload,
    headers={
        "Authorization": "Bearer ...",
    },
    timeout=10.0,
)

response.raise_for_status()
data = response.json()

逐行到底发生了什么

1
httpx 把 dict 序列化

json=payload 会准备 JSON body 和相应 Content-Type。

2
网络等待

程序等待 DNS/TCP/TLS/服务端处理和响应。这里正是后面 async 能发挥作用的地方。

3
raise_for_status()

4xx/5xx 不再静默当成“正常结果”继续往下跑。

4
response.json()

把响应 JSON 解析成 Python 对象，后续才能交给 Pydantic / Agent。

为什么要 timeout？没有超时边界，外部服务如果长时间不返回，你的请求、worker、Agent task 都可能一直挂着占资源。
7

错误示范：一段“能跑”的 API 代码有哪些隐患？

真正面试常问的不是 httpx.post 会不会写，而是你有没有边界意识。
def call_api(data):
    response = httpx.post(URL, json=data)
    return response.json()
❌ 没 timeout

请求可能无限等。

❌ 不检查 status

500 返回的错误 JSON 也可能被当正常业务数据。

❌ 没验证 response schema

供应商结构一变，错误会在更深处才爆。

❌ client 层职责不清

如果这里顺便决定 Agent retry/fallback，网络层和业务编排又混在一起。

更健康的边界

class SearchClient:
    def __init__(self, base_url: str, api_key: str):
        self.base_url = base_url
        self.api_key = api_key

    def search(self, request: SearchRequest) -> SearchResponse:
        response = httpx.post(
            f"{self.base_url}/v1/search",
            json=request.model_dump(),
            headers={"Authorization": f"Bearer {self.api_key}"},
            timeout=10.0,
        )
        response.raise_for_status()
        return SearchResponse.model_validate(response.json())
注意它只负责：把合法请求送出去 → 把合法响应带回来。要不要 retry、换备用服务、告诉用户失败，仍然可以留给更上层 Agent / service 决策。

接口返回 401。应该：① 立刻 retry 10 次；② 检查认证配置；③ 把 JSON 继续交给 Agent。选哪个，为什么？

答案

②。401 通常不是“再试一次就会好”的临时故障。应检查 key、权限或认证头。

Module 和 Package：先把“房间”和“楼层”分清

不要死背定义，先看它们解决什么组织问题。
🚪
Module = 一个 .py 文件

search.py 就是一个 module。它最好围绕一组相关行为。

🏢
Package = 一组相关 modules

tools/ 把 search.py、pdf.py、calculator.py 组织在一起。

你可以把 module 理解成办公室，package 是一层楼。目的不是“目录看着整齐”，而是让职责和依赖边界变得清楚。

真正重要的是“依赖方向”，不是目录长得漂亮

一个好结构让高层编排依赖底层能力，而不是所有模块互相 import。
agents/决定流程：什么时候搜索、什么时候问模型
↓ 调用
tools/执行搜索、PDF、计算
services/LLM / DB / 外部 client
models/稳定的数据结构
坏味道：tools/search.py 反过来 import agents/research_agent.py。工具层突然知道了上层 Agent，依赖方向开始打结。

哪一种依赖更健康？

import 到底发生了什么？

它不是“复制粘贴另一个文件”，而是让当前模块获得另一个模块暴露的名字。
# app/agents/research_agent.py
from app.tools.search import search_papers
from app.services.llm import get_llm


def run_agent(question: str):
    papers = search_papers(question)
    llm = get_llm()
    return llm.summarize(papers)
research_agent.py
import
tools/search.py
拿到
search_papers

为什么会有 circular import？

agent.py
import search
→
search.py
又 import agent
↩

Python 正在初始化 agent.py 时跑去初始化 search.py；search.py 又要求一个“还没初始化完”的 agent.py。循环就出现了。

修 circular import 最好的第一反应：不要先想“怎么绕开 import 语法”，先问职责是不是放错了。共享数据模型可抽到 models；公共能力可抽到更底层模块。

__init__.py、__main__、运行入口：先学够用的

这些名字容易吓人，但对 Agent 项目只需要先掌握最常用部分。
东西先这样理解现在需要会什么
__init__.pypackage 初始化文件 / 明确包边界知道它可以为空，也可以重导出少量公共接口
if __name__ == "__main__"“直接运行这个文件时才执行”避免 import 时顺手启动整个程序
python -m app.main以 module 方式从项目根执行比在子目录乱跑脚本更不容易破坏 import 路径
# app/main.py
from app.agents.research_agent import run_agent


def main():
    answer = run_agent("RAG evaluation")
    print(answer)


if __name__ == "__main__":
    main()
常见新手坑：为了“让 import 能用”，到处手改 sys.path。很多时候真正问题是你不在项目根运行、package 结构不对，或者安装方式不对。

pyproject.toml、虚拟环境、.env：它们不是杂项

一个工程除了 Python 文件，还得说明“我依赖什么、怎么安装、运行时配置从哪来”。
📦
pyproject.toml

项目元数据、Python 版本、依赖、工具配置。别人拿到仓库才知道该装什么。

🫧
.venv

给这个项目独立的 Python 环境，不让全局包版本互相污染。

🔐
.env

本地运行时配置。API key 可以从环境读取，但 .env 本身不要 commit。

练习 A · 重构

把一个同时包含 SearchRequest、search_papers()、call_llm()、run_agent() 的 main.py 拆到上面的目录。

参考拆法

SearchRequest → models/schemas.py；search_papers → tools/search.py；call_llm → services/llm.py；run_agent → agents/research_agent.py；main.py 只负责启动。

练习 B · 找架构 bug

tools/search.py 里 import run_agent，因为搜索失败后“想让 Agent 决定怎么办”。为什么不理想？

思考方向

错误恢复决策属于上层编排。SearchTool 更适合返回明确结果/异常，让 Agent 决定 retry、fallback 或停止，而不是工具反向控制 Agent。

Python 05 · Research Agent v0.5

async 不是“让代码更快”。
它是别在等待时发呆。

上一课我们第一次让 Research Agent 调外部 API。现在一个新问题出现了：搜索 arXiv、Web、Crossref 都要等网络。如果一个一个等，程序大量时间什么都没做。

1

先看同一个任务，为什么会差 5 秒

三个请求分别要 3s、4s、2s。切换同步 / 异步，看等待时间怎么变化。
先记一句：如果任务主要在“等网络、等数据库、等文件”，这些等待往往可以重叠。
arXiv
arXiv · 3s
Web
Web · 4s
Crossref
Crossref · 2s
总等待约 9 秒
注意：这不是说 async 把 3 秒网络变成 1 秒。单个请求并没有更快，只是多个“等待”重叠了。
2

Event Loop 到底在做什么？

把它想成一个只负责“谁现在能继续执行”的调度员。
A · 发出 LLM 请求
B · 查数据库
C · 搜索网页
EVENT
LOOP
LLM API · 等待中
DB · 等待中
Search · 等待中

当 A 执行到 await，它不是“把整个程序暂停”。更准确地说：A 暂时不能继续，于是把控制权还给 event loop；event loop 去推进 B 或 C。

所以 await 最重要的直觉不是“等待”，而是“这里允许暂时让出执行权”。
3

代码要分四步长出来

最容易学歪的是：看到 async/await 就以为自动获得并发。
1
完全同步：真的一个个等
a = search_arxiv()
b = search_web()
c = search_crossref()
2
函数变 async，只代表它可以挂起
async def search_arxiv():
    ...
3
这样仍然是串行等待
a = await search_arxiv()
b = await search_web()
c = await search_crossref()

每一行还是等完才走下一行。

4
真正并发：同时安排多个 coroutine
results = await asyncio.gather(
    search_arxiv(),
    search_web(),
    search_crossref(),
)
4

Coroutine、Task、gather 不要混成一团

面试经常不是问语法，而是问这些对象到底代表什么。
概念ELI5工程直觉
coroutine一张“可以暂停继续”的任务说明书调用 async function 得到 coroutine object，不代表已经完成
Task已经被 event loop 安排执行的工作create_task() 后会被调度
await我现在等这个结果，期间把控制权让出去当前 coroutine 挂起
gather把多件事一起安排，最后收齐结果适合一组独立 I/O 请求

哪一段“看起来 async”，但仍然串行？

5

并发也不是越大越好

10 个请求同时发很爽，那 1000 个呢？
并发上限3

真实项目里为什么会用 Semaphore？

sem = asyncio.Semaphore(5)

async def limited_search(query):
    async with sem:
        return await search_api(query)
目的不是故意变慢。它是在吞吐、供应商 rate limit、连接池、内存、成本之间做控制。无脑 gather(*1000_requests) 很可能直接换来 429。
6

async 最常见的误解：它不能让 CPU 重活变快

网络等待和矩阵计算是两类完全不同的问题。
🌐
I/O-bound

LLM API、HTTP、数据库、文件读取。大量时间在等外部世界，async 很适合。

🧮
CPU-bound

大矩阵、图像处理、重型 Python 计算。event loop 自己也会被占住，async 不会凭空增加 CPU。

async def bad_endpoint():
    huge_cpu_calculation()   # 这里一直占着 event loop
    return {"ok": True}
后果：虽然函数写着 async，但里面的重 CPU 同步代码会阻塞 event loop。其他请求照样卡住。CPU-heavy 通常要考虑进程池、任务队列或外部计算服务。
7

Research Agent v0.5：把多源检索真正并发起来

现在 v0.4 的 HTTP client 开始有“并发策略”。
import asyncio

async def gather_evidence(query: str):
    arxiv, web, crossref = await asyncio.gather(
        search_arxiv(query),
        search_web(query),
        search_crossref(query),
    )

    return {
        "arxiv": arxiv,
        "web": web,
        "crossref": crossref,
    }
练习 A · 找问题

下面代码为什么没有真正并发？

async def gather_evidence(query):
    a = await search_arxiv(query)
    b = await search_web(query)
    return a, b
答案

因为第二个请求直到第一个 await 完成后才开始。async function 不等于自动并发。

练习 B · 工程选择

你要并发调用 200 个 LLM 请求，是不是直接 gather() 全部最好？

答案

通常不是。应结合 rate limit、连接池、任务优先级和成本设置并发上限，常见手段包括 Semaphore、队列或 worker。

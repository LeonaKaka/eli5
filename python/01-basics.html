两个名字可指向同一对象

因此修改 list/dict 时，要问“我是在改对象，还是让变量重新指向另一个值？”

state = {"retry_count": 0}
backup = state

backup["retry_count"] += 1

print(state["retry_count"])

预测输出

为什么答案是 1？

backup = state 没复制 dict；两个变量都指向同一个 dict。通过 backup 修改这个 dict，state 看到的当然也是修改后的对象。

if 和 for：一个负责“选路”，一个负责“重复”

Agent loop 看起来高级，拆开其实就是判断和重复。
if = 决策
if score >= 0.8:
    keep(paper)
else:
    discard(paper)

条件只决定“这一刻走哪条分支”。

for = 对一组对象逐个处理
for paper in papers:
    score = rank(paper)

重点是“这一组数据已经存在”。

错误示范：函数偷偷依赖全局变量

threshold = 0.8

def select_good_papers(papers):
    # 能跑，但函数行为偷偷依赖外部状态
    return [p["title"] for p in papers if p["score"] >= threshold]
为什么不理想？测试和复用都更难。调用者只看函数签名，不知道 threshold 还藏在外面。下一课我们会把“函数接口必须清楚”推到 Type Hint + Pydantic。

任务

实现一个 select_good_papers()：输入论文列表和 threshold，返回保留论文的 title；遇到缺少 score 的论文先跳过。

参考实现
def select_good_papers(papers, threshold=0.8):
    selected = []

    for paper in papers:
        if "score" not in paper:
            continue

        if paper["score"] >= threshold:
            selected.append(paper["title"])

    return selected

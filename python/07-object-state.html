Python 07 · Research Agent v0.7

class 不是为了“高级”。
是当一组状态和行为总在一起时，把它们收拢。

前六课后，Agent 已经有 model、tools、messages、retry_count、finished、logging、并发策略。如果这些东西继续散落在函数参数和全局变量里，维护成本会快速上升。

1

先看问题：状态开始满天飞

当同一组数据总是一起出现，你会自然想给它一个名字。
model = "model-x"
tools = ["search", "python"]
messages = []
retry_count = 0
finished = False

async def run_agent(model, tools, messages, retry_count, finished, question):
    ...
不是“不能写”。问题是参数越来越长，而且这些值之间其实有明确关系：它们共同描述“一个 Agent 当前是什么状态”。
这一课目标：学会判断什么时候函数就够，什么时候 dataclass/class 更自然；并避免为了 OOP 而 OOP。

它特别适合“主要用于保存数据，行为不复杂”的对象。

3

最经典的坑：可变默认值为什么要 default_factory

list / dict 是可变对象。多个实例共享同一个默认 list 会产生非常隐蔽的状态污染。
❌ 错误直觉：共享同一 list
agent_a.messages → 0xABC
agent_b.messages → 0xABC
✅ 正确：每个实例各自创建 list
agent_a.messages → 0x111
agent_b.messages → 0x222
@dataclass
class AgentState:
    messages: list[dict] = field(default_factory=list)
面试高频：为什么不能把 [] 直接当成所有实例共用的可变默认对象？核心就是“默认值对象是否被多个实例共享”。

Composition：Agent “拥有工具”，不必“继承工具”

AI 工程里更常见的是把不同能力组合起来，而不是做一棵复杂继承树。
ResearchAgent
负责流程与状态
HAS →
LLMClient
SearchTool

class ResearchAgent:
    def __init__(self, llm, search_tool, memory):
        self.llm = llm
        self.search_tool = search_tool
        self.memory = memory
Composition 的好处：测试时可以把真实 SearchTool 换成 FakeSearchTool；换模型供应商时替换 LLMClient；Agent 本身不用继承一堆供应商类。
错误方向：class ResearchAgent(OpenAIClient, SearchTool, RedisMemory, Logger)。这种多重继承会把“会使用这些能力”和“本身就是这些能力”混在一起。
6

Pydantic Model、dataclass、普通 class 到底怎么选？

它们不是互相替代，而是解决不同问题。
工具最适合Agent 例子
Pydantic BaseModel外部边界、验证、序列化SearchRequest / API Response / Tool 参数
dataclass内部结构化状态，想少写样板代码AgentState / ToolResult
普通 class长期持有依赖并提供行为ResearchAgent / SearchService
普通 dict/list局部、简单、短生命周期数据一个函数内部临时聚合结果
不要追求“统一成一种”。一个真实项目里同时出现 Pydantic、dataclass、class、dict 非常正常。

Research Agent v0.7：把状态、依赖、行为收拢

现在项目第一次有了一个真正清楚的 Agent 对象。
from dataclasses import dataclass, field

@dataclass
class AgentState:
    messages: list[dict] = field(default_factory=list)
    retry_count: int = 0
    finished: bool = False

class ResearchAgent:
    def __init__(self, sources, logger):
        self.sources = sources
        self.logger = logger
        self.state = AgentState()

    async def run(self, question: str):
        self.state.messages.append({"role": "user", "content": question})
        results = await self._search_all(question)
        self.state.finished = True
        return results

练习 B · 工程选择

一个 parse_json(text) 只输入字符串并返回 dict，没有长期状态。该不该强行写成 Parser class？

参考思路

通常没必要。纯函数更直接、更容易测试。只有当 parser 长期持有配置、缓存、schema、外部资源时，class 才更自然。

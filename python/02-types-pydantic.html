对应的 Pydantic 模型

from pydantic import BaseModel, Field

class SearchRequest(BaseModel):
    query: str
    top_k: int = Field(
        default=5,
        ge=1,
        le=20,
    )
东西职责
query: str类型契约：query 应该是字符串
top_k: int类型契约：top_k 应该是整数
ge=1, le=20业务约束：即使是整数，也必须在合理范围

为什么 AI 工程特别依赖 Schema？

因为 LLM 本身是不确定的，而工具和 API 通常要求确定的数据结构。
LLM
自由文本能力
→
Schema
规定形状
→
Validation
检查合法
→
Python Tool
确定执行
🛠️
Tool Calling

工具参数必须能解析成明确字段，不是让模型写一段“差不多像参数”的自然语言。

📤
Structured Output

让模型返回明确结构，便于程序继续消费，而不是人工阅读。

⚡
FastAPI

HTTP 请求进入后自动按模型验证，错误尽早返回给调用者。

所以 Pydantic 不只是“Python 小知识”。它是你后面理解 FastAPI request model、LLM structured output、tool schema 的共同底座。

6

错误示范：把“所有东西”都做成 Pydantic

数据验证很重要，但不是每个内部临时变量都需要一个 Model。
适合 Pydantic

用户输入、API request/response、LLM structured output、Tool 参数、配置。

普通 Python 就够

函数内部临时 list、只在一个小函数中使用的局部变量、没有外部边界的数据。

工程判断：“哪里需要严格契约”比“Pydantic 用得越多越专业”重要。过度建模同样会让代码变重。

from pydantic import BaseModel, Field

class SearchRequest(BaseModel):
    query: str
    top_k: int = Field(default=5, ge=1, le=20)

def handle_search(raw_data: dict) -> list[str]:
    request = SearchRequest.model_validate(raw_data)

    return search_papers(
        query=request.query,
        top_k=request.top_k,

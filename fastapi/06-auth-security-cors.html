`X-Tenant-ID: tenant-a` 不是身份。
客户端自己写的 tenant 也不是授权。

前四课为了教学依赖注入，暂时让 header 提供 tenant。现在正式撤掉这个信任：Authorization → authenticate principal → derive tenant → check permission → scope resource。同时把浏览器 CORS 和反向代理 forwarded headers 也放回正确的安全边界。

旧版为什么危险？

GET /runs/run-42
X-Tenant-ID: tenant-a

如果服务器直接相信：
tenant_id = request.headers["X-Tenant-ID"]

攻击者只要改成：
X-Tenant-ID: tenant-b
→ 越权尝试

Header 只是输入。除非它来自你已经验证过的可信上游并且链路边界明确，否则不能因为“它在 header 里”就升级成 identity。

6
FastAPI Security primitive 在这里负责什么？
bearer_scheme = HTTPBearer(
  scheme_name="BearerAuth",
  auto_error=False,
)

async def get_current_principal(
    credentials = Security(bearer_scheme),
):
    ... authenticate ...

RunApprovePrincipal = Annotated[
    Principal,
    Depends(require_permission("runs:approve")),
]
这样 OpenAPI 会声明 HTTP Bearer security scheme；但 FastAPI 只帮你抽取认证材料和组织 dependency，真正 token 验证/授权策略仍是应用逻辑。
7
CORS：浏览器能不能跨 Origin 调你，不等于你有没有权限
Frontend
Origin: `https://app.example.test`
Authorization: Bearer ...
→
CORSMiddleware
origin / method / headers preflight
然后真正 request 仍走 auth + authz
app.add_middleware(
  CORSMiddleware,
  allow_origins=["https://app.example.test"],
  allow_credentials=True,
  allow_methods=["GET","POST","OPTIONS"],
  allow_headers=[
    "Authorization",
    "Content-Type",
    "If-Match",
    "Idempotency-Key",
    "Last-Event-ID",
  ],
)
有 credentials 时不要图省事全 `*`。当前 FastAPI/Starlette CORS 规则要求 credentials=true 时 origin/method/header 都显式配置，Bearer Authorization 也正属于 credentialed communication。
8
反向代理 Header 是另一条 trust boundary
Client可以自己伪造 `X-Forwarded-For / Proto / Host`。
Trusted proxy / LB清洗并重新设置 forwarded headers。
Uvicorn / FastAPI server只有配置 trusted proxy IP 后才应该解释这些 header。
当前官方文档通过 `--forwarded-allow-ips` 配置允许信任的代理来源。把它设成 `*` 只有在网络拓扑保证“只有可信 proxy 能直接访问 app server”时才合理。

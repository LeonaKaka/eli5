真正的 API contract 不只是“body 能 parse”。
它还要决定什么能进来、什么能出去、谁属于哪个 tenant。

FastAPI 最强的地方不是 decorator，而是把 Python 类型、Pydantic schema 和 dependency graph 变成一套可验证的 HTTP contract。本课把 `CreateRunRequest`、`RunResponse`、`Annotated + Depends` 和 tenant boundary 接起来。

1

输入模型和输出模型必须分开

内部 RunRecord 不是 API response。

不要 `return run.model_dump()`。RunRecord 里还有 tenant_id、checkpoint_id、approval_request_id、budget 等内部控制字段；它们不应该因为“已经在对象里”就自动泄露给客户端。

FastAPI 的 response model 会参与序列化、验证和 OpenAPI；更重要的是，它逼你显式设计“API 允许看到什么”。

3

Pydantic 不只检查类型，还定义边界行为

class CreateRunRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")

    objective: str = Field(
        min_length=1,
        max_length=4000,
    )
    approval_required: bool = False
未知字段
→
extra=forbid
→
422

如果客户端偷偷加 `admin=true`，API 不会“顺手忽略然后继续”。边界 contract 越明确，后面权限和升级越不容易出现 shadow fields。

4

`Depends` 是依赖图，不只是少写几行参数

async def get_tenant_context(
    x_tenant_id: Annotated[
        str,
        Header(alias="X-Tenant-ID")
    ],
) -> TenantContext:
    ...

TenantDep = Annotated[
    TenantContext,
    Depends(get_tenant_context),
]

→

→

→

FastAPI 会调用 dependency、把它的输入也加入 OpenAPI，并把返回值注入 endpoint。官方当前也推荐 `Annotated + Depends` 写法。

6
这版 Tenant Header 只是教学输入，不是真实认证
⚠ 现在的教学 baseline
X-Tenant-ID: tenant-a
客户端自己声明 tenant。适合本课看 dependency/isolation contract，不适合生产。
✅ 生产方向（第 06 课）
Authorization: Bearer ...
        ↓
authenticate identity
        ↓
derive allowed tenant/workspace
tenant 应来自认证身份和授权关系，而不是相信用户随便写的 header。
7
Dependency 注入 runtime，也避免全局对象到处 import
def get_bridge(request: Request):
    return request.app.state.bridge

BridgeDep = Annotated[
    ProductionGraphBridge,
    Depends(get_bridge),
]
后面测试时可以替换 dependency；生产 lifespan 里也能把数据库、HTTP client、queue adapter 作为 app-owned resource 管理，而不是模块 import 时偷偷初始化。
8
OpenAPI 会包含 dependency 的 header requirement
POST/runsX-Tenant-ID requiredGET/runs/{run_id}X-Tenant-ID required
所以 dependency 不是“运行时黑盒”。它声明的 Header/Query/Cookie 等输入也会进入 HTTP schema。

Mock 的目的不是让所有东西变假。
而是精准切断“这次测试不想测”的边界。

FastAPI 的 dependency graph 很适合测试替换：`app.dependency_overrides` 可以把真实 IdP、数据库 adapter 或昂贵外部服务换成 deterministic fake。但 Queue/revision/interrupt 这些你真正担心的机制，必须在 integration test 里继续跑真的。

3
`app.dependency_overrides` 到底替换什么？
HTTPBearer→get_current_principal→require_permission→route
async def fake_principal():
    return Principal(
      subject="test-user",
      tenant_id="tenant-test",
      permissions={"runs:read"},
    )

app.dependency_overrides[
    get_current_principal
] = fake_principal
FastAPI 会使用 override，不再执行被替换 dependency 的原始子依赖。这样 endpoint-unit test 不需要伪造真实 bearer token 或调用外部 IdP。


4
为什么还要 override `get_bridge`？
class FakeBridge:
    control.store.get(...)
      → fixed RunRecord(revision=7)

app.dependency_overrides[get_bridge] = fake_bridge

GET /runs/run-unit
→ 200
→ ETag: "7"
这条测试只问：“给定一个已授权 Principal 和一个 RunRecord，HTTP endpoint 是否正确投影资源？”它不应该顺便测试 Queue、LangGraph 和 worker。

前面已经有的测试仍然负责：submitted Run 是否保持 QUEUED、重复 job 是否被 revision 拒绝、approval 是否只 enqueue 一次 RESUME、interrupt checkpoint 是否写回产品 Run。
Over-mock 症状：测试里自己返回 `{"status":"queued"}`，然后 assert 它等于 queued。这只证明 fake 会返回你写进去的值。

7
测试错误协议时，别只 assert status code
response = client.post(...invalid body...)

assert response.status_code == 422
assert response.headers["content-type"] \
       .startswith("application/problem+json")
assert body["code"] == "validation_error"
assert body["request_id"] == \
       response.headers["x-request-id"]
assert "secret-input" not in response.text
这样同时锁住协议形状和“不泄露原 body / stack trace”的安全属性。


8
500 测试为什么要 `raise_server_exceptions=False`？
client = TestClient(
    app,
    raise_server_exceptions=False,
)

GET /_test/boom
→ RuntimeError("private-secret")
→ exception handler
→ 500 ProblemDetails

assert "private-secret" not in response.text
默认 TestClient 会把服务端异常重新 raise 给测试进程，适合调试；要测试最终 500 HTTP response，就需要让异常走完整 ASGI error path。

Checkpointer 记“这条 thread 跑到哪”。
Store 才记“换一条 thread 以后仍值得知道什么”。

LangGraph persistence 有两层：checkpointer 保存 thread-scoped Graph State；Store 保存跨 thread 的 application-defined data。真正难的不是 `store.put()`，而是谁能写、写到哪个 namespace、什么值得跨 run 保存、旧事实怎么失效。所以 v4.7 继续复用 Agent 04 的 MemoryWritePolicy，而不是让 Store 绕过它。

Graph node 通过 Runtime 访问 Store 和 Context
@dataclass
class MemoryContext:
    user_id: str

builder = StateGraph(State, context_schema=MemoryContext)
graph = builder.compile(checkpointer=checkpointer, store=store)

def recall(state, runtime: Runtime[MemoryContext]):
    ns = ("user", runtime.context.user_id, "memories")
    items = runtime.store.search(ns)
`thread_id` 放 config；`user_id/workspace_id` 更适合作为 runtime context。两个标识解决的 scope 不同。
5
Store 不是“观察到什么就写什么”
Observation
→

→
scope / source / confidence / reusable / verified / sensitive

v4.7 刻意保留原来的 write gate。敏感信息、working memory、未验证 semantic fact、没有跨 run 复用价值的信息，不会因为“现在有 Store 了”就自动长期化。
6
Namespace prefix 很强，也很容易搜宽
Store search 是 namespace-prefix 语义。`("user","user-42")` 可能命中它下面多个子 namespace；需要精确 scope 时就给完整 namespace 或再做应用过滤。
7
同一个 key 的 put 是 overwrite；历史语义要自己设计
LangGraph Store 是 key/value store。相同 namespace + key 再 `put` 会更新该 item。v4.7 adapter 刻意拒绝 silent overwrite：
if store.get(namespace, memory_id) is not None:
    raise ValueError("use a new immutable id or explicit invalidation")
纠正事实时走显式 `invalidate_store_memory()`，而不是偷偷把旧 memory 改成另一句话。
8
Semantic search 是可选能力，不是 Store 的定义
Store 不配置 embedding 时也可以做 key/value、namespace listing 和普通搜索。要 semantic retrieval 才需要 index/embed 配置。
这正好对应 RAG 课学过的原则：存储层和检索策略分开。不要因为长期记忆用了 Store，就默认每条 memory 都必须向量化。

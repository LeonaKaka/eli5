09 · Research Assistant v4.9

生产 Agent 不能只问“最后输出是什么”。
你还要知道每一步发生了什么，以及跨切面规则在哪里执行。

Middleware 解决的是 logging、budget、retry、guardrail、dynamic prompt/tool/model 这类横跨很多节点的 concern；Streaming 解决的是运行中把 state update、完整 state、token、checkpoint、task 或业务 progress 暴露出来。两个概念经常一起出现，但职责完全不同。

1

为什么不要把 logging / budget / retry 复制进每个 node？

那会让业务逻辑和运行策略粘死。
❌ 每个 node 自己写
def retrieve(...):
  check_budget()
  log()
  retry(...)
  ...business...

def write(...):
  check_budget()
  log()
  retry(...)
✅ Middleware / runtime layer
create_agent(
  model=model,
  tools=tools,
  middleware=[
    CallBudgetMiddleware(),
    ...
  ]
)

业务节点只保留业务语义；cross-cutting policy 放到 hook。

2

Middleware hook 到底在哪些地方插进去？

Node-style hook 和 wrap-style hook 不是一回事。
before_agent→before_model→model→after_model→before_model→model→after_model→after_agent

Node-style适合日志、校验、state update；wrap_model_call / wrap_tool_call包住一次真实调用，适合 retry、cache、fallback、请求变换。
3
v4.9：把模型调用预算做成真实 AgentMiddleware
业务 graph 不需要知道预算实现细节。
class CallBudgetMiddleware(AgentMiddleware):
    @hook_config(can_jump_to=["end"])
    def before_model(self, state, runtime):
        if state.get("model_call_count", 0) >= self.max_model_calls:
            return {
              "blocked_by_budget": True,
              "jump_to": "end",
            }

    def after_model(self, state, runtime):
        return {
          "model_call_count": state.get("model_call_count", 0) + 1
        }
Middleware 也不是安全魔法。它适合 agent runtime 的横切逻辑；tenant authorization、真实资源 ACL、外部幂等仍应在 Tool / application boundary 再检查。

为什么 v2 stream envelope 更适合生产 adapter？
所有 mode 都有统一 type / namespace / data 外壳。
for part in graph.stream(
    inputs,
    stream_mode=["updates", "custom"],
    version="v2",
):
    print(part["type"])
    print(part["ns"])
    print(part["data"])
Subgraph 时 `ns` 能告诉你事件来自哪个 namespace；前端 adapter 可以按 `type` 做稳定分发，而不是猜 tuple 形状。
7
Streaming ≠ Observability
用户看得到进度，不代表你能做生产诊断。
Product stream给用户：token、phase、artifact ready、approval request。
Operational telemetry给工程：latency、tool errors、queue wait、retry、checkpoint、cost。
Eval trace给质量：tool choice、unnecessary step、handoff/recovery、policy violation。
三类数据可以来自同一次 run，但消费者和保留策略不同。不要为了 UI stream 把 secret/debug payload 全广播给客户端。

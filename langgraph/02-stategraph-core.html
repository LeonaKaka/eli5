02 · Research Assistant v4.2

StateGraph 的核心不是“画流程图”。
而是让 State 的变化和控制流都有明确规则。

一个 Graph 真正难的不是 `add_node()`，而是三个问题：State 里到底放什么？Node 只返回哪些 update？多个 update 遇到同一个字段时怎么 merge？这就是 reducer。搞不清 reducer，图可以跑，但状态迟早会被悄悄覆盖。

1

先看这条最小心智模型

LangGraph 官方 Graph API 也是围绕 State / Nodes / Edges 三件事组织。
State
→
Node
→
Partial Update
→
Reducer
→
New State
Edge 决定下一个 Node；Reducer 决定 update 怎样并入 State。这是两个完全不同的职责。
2

一个 Node 不应该每次返回整个 State

返回它真正改变的字段即可。
def classify_request(state: ResearchGraphState):
    return {
        "route": "research",
        "events": ["classify:research"],
        "step_count": state["step_count"] + 1,
    }

这里没有返回 `objective / evidence / answer`，它们仍留在 State 里。LangGraph 把这个结果当作一个 state update，再按字段的 reducer 规则应用。

如果每个 Node 都手工复制整个 State，你会重新发明一套容易漏字段、覆盖字段的 reducer。

4
Reducer 是 merge semantics
默认不是 append，而是 overwrite。
State schema
class State(TypedDict):
    answer: str | None
    events: Annotated[list[str], add]
`answer` 没 reducer → 新 update 覆盖旧值。`events` 有 `operator.add` → list 拼接。
现场结果
旧: ["classify"]
新 update: ["research"]
结果: ["research"]

默认 reducer 会覆盖旧值。
最危险的 bug：你以为两个并行 Node 都在“追加结果”，但字段没有 reducer，于是其中一个 update 把另一个覆盖掉。


5
State 不是 Messages 的同义词
Conversation 只是 State 的一种可能字段。
class ResearchGraphState(TypedDict):
    objective: str
    route: Literal["research", "direct"] | None
    evidence: Annotated[list[str], add]
    events: Annotated[list[str], add]
    step_count: int
    answer: str | None
你前面 Agent 课程已经见过同样原则：控制面状态不应该全塞进聊天记录。Graph State 可以包含 messages，也可以包含 route、evidence ids、budget counters、plan revision、approval refs 等。
LangGraph 提供 `MessagesState`，适合“messages 是核心状态”的应用；但复杂 Research Assistant 更应该扩展它或定义自己的 State，而不是把所有业务字段序列化进 system message。


6
Fixed Edge 和 Conditional Edge
一个是确定下一步，一个是让路由函数读取 State 决定下一步。
Fixed
builder.add_edge(
    "research",
    "synthesize",
)
research 完成后永远进入 synthesize。
Conditional
builder.add_conditional_edges(
    "classify",
    route_after_classify,
    {
      "research": "research",
      "direct": "direct",
    },
)
分类结果成为显式控制流，而不是藏在某个 Node 内部继续调用函数。


7
`START` / `END` 不是装饰
它们给 Graph 一个明确入口和终止边界。
builder.add_edge(START, "classify")
...
builder.add_edge("synthesize", END)
前面你手写 `AgentLoop` 时，start/stop 是 while-loop 外层代码；Graph 里它们成为图结构的一部分。之后 checkpoint、stream、interrupt 都会依赖这个执行模型。


8
为什么必须 `compile()`？
Builder 只是图定义，compiled graph 才是 runnable runtime。
builder = StateGraph(ResearchGraphState)
# add nodes / edges ...

graph = builder.compile()
result = graph.invoke(initial_state)
官方文档把 compile 描述成构建后的必要步骤：它会做基本结构检查，同时也是未来注入 checkpointer / breakpoint 等 runtime 配置的地方。
把它理解成：Graph definition → validated executable runtime，而不是 Python 语法上的多余仪式。

Research Assistant v4.2：第一次真正有 Graph State
项目不是页面模拟，源码已经使用 `StateGraph`。
graph = build_research_state_graph()

result = graph.invoke(
    initial_research_state(
        "compare paper A and paper B",
        mode="research",
    )

assert result["events"] == [
    "classify:research",
    "research",

这条测试同时锁住三件事：conditional route 生效、`events/evidence` reducer 保留累积结果、direct 分支会跳过 research 但重新汇合到 synthesis。

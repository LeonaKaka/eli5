Subgraph 不是“另一个 Agent”的同义词。
它首先是一个有明确输入/输出边界的可组合 Graph。

LangGraph subgraph 可以只是可复用 workflow，也可以成为 specialist agent。真正设计时先问：父子是否共享 State key？child 是否需要 private scratch？是否需要跨调用保持自己的 checkpoint？handoff 时到底传哪些上下文？这些问题比“我要几个 Agent”更重要。

1

什么时候 subgraph 值得存在？

Reusable workflow

同一组 nodes 要被多个 parent graph 复用。

Specialist boundary

检索、写作、代码等需要独立 state/schema/工具边界。

Team ownership

不同团队只约定 subgraph input/output，不必知道内部节点。

不值得拆

只是给同一个模型换个角色名，没有真实状态/权限/实现边界。

2

两种最基本的父子通信模式

模式适合情况做法
Shared keysparent / child 有共同 channelcompiled subgraph 直接 `add_node`
Different schemaschild 有 private state 或完全不同 schemawrapper node 显式 map input/output
不要为了“省 mapping”强行让所有 agent 共用一个巨型 State。Private state 本身就是控制上下文污染的一种手段。

Shared state：可以直接把 compiled subgraph 当 node
child = child_builder.compile()

parent = StateGraph(ParentState)
parent.add_node("retrieval_subgraph", child)
如果 parent 和 child 都有 `objective / evidence`，child 可以直接读写这些 channel。child 还可以有自己的 `scratch`，但 parent schema 没这个 key，就不应该把它当父图业务状态。
5
Private state：wrapper 是显式 context engineering
def call_writer(parent_state):
    child_result = writer_graph.invoke({
        "question": parent_state["objective"]
    })
    return {
        "specialist_result": child_result["draft"]
    }

这比“把 parent 全部 state/messages 原样传进去”更容易审计，也更省 context。
6
`Command.PARENT`：child 可以把控制权交回父图的另一个节点
return Command(
    update={
      "handoff_payload": evidence_summary,
      "events": ["handoff:retriever→writer"],
    },
    goto="writer_agent",
    graph=Command.PARENT,
)
这和普通 `goto` 不同：目标节点存在于 parent graph。v4.8 用它把 retriever subgraph 的最小 evidence payload 交给 sibling `writer_agent`。
不要给同一个 node 同时写 static edge 和 Command goto。Command 只增加动态路由，static edge 仍会照样执行，可能导致两个下游都跑。
7
Handoff 最难的是 context，不是 goto
❌ 整段内部历史
retriever scratch、内部 retries、无关 tool messages 全塞给 writer。
✅ 最小 handoff contract
objective + verified evidence ids/summary + required provenance + ownership event。
如果 handoff 是由 ToolCall 触发，还要保持 AIMessage/tool call 与 ToolMessage 的配对，否则接收方会看到 malformed message history。
8
Subgraph persistence：None / True / False 不是布尔小细节
compile(checkpointer=)语义适合
`None` 默认per-invocation；继承 parent checkpointer 支持本次 durable execution，但下次调用 fresh多数独立 specialist 请求
`True`per-thread；同一 thread 下 child 自己积累 state需要 multi-turn specialist memory
`False`stateless；不 checkpoint纯函数式、无需 interrupt/recovery
per-thread subgraph 还会引入 checkpoint namespace 并发约束。同一 subgraph instance 不能随便被平行调用多次，否则会发生 namespace conflict。

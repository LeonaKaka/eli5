ToolNode 不是“帮你调用 Python 函数”。
它接管的是一整套 Tool Message 协议和循环节点。

前面你手写过 `ToolCall → ToolExecutor → Observation → next decision`。LangChain / LangGraph 里，标准工具循环通常表现成：模型产生带 `tool_calls` 的 `AIMessage`，`ToolNode` 执行工具并写回 `ToolMessage`，然后模型再次读取结果。真正关键的是：Tool call、Tool result 和下一轮模型输入之间必须靠稳定消息协议关联。

1

先把“工具函数”和“Agent 工具循环”分开

`@tool` 只是定义 Tool；Agent loop 还需要 model routing 和 result feedback。
Python function

普通函数，自己决定参数和返回值。

@tool

把名字、描述、参数 schema 暴露给模型/Tool runtime。

ToolNode

读取最后一个 AIMessage 里的 tool_calls，执行注册工具，生成 ToolMessage。

tools_condition

最后 AIMessage 有 tool_calls → tools；没有 → END。

所以 `ToolNode` 不是决策者。它执行模型已经提出的 ToolCall；“该不该调用哪个 Tool”通常仍由 model node 或应用 policy 决定。

4

`@tool` 最重要的是 schema 和 description

模型不是靠读 Python 源码来猜怎么调用 Tool。
from langchain.tools import tool

@tool
def search_papers(query: str) -> str:
    """Search papers relevant to a research query."""
    ...

这里至少暴露出：Tool 名、描述、参数 `query: str`。真实工具如果 schema 模糊、描述重叠，模型 tool-choice 准确率就会下降。

这和前面 Agent 09 的 Tool-choice Eval 是同一件事：框架帮你规范协议，不会替你自动写出高质量工具边界。
5

ToolNode 执行什么，不执行什么？

框架执行节点 ≠ 授权系统。
ToolNode 擅长

解析 tool_calls、调用已注册 Tool、处理 ToolMessage、并行执行多个 ToolCall、按配置处理错误。

仍然是应用责任

tenant 权限、side-effect approval、secret scope、外部幂等契约、业务级 destructive policy。

危险误区：“这个工具只注册给 Agent，所以模型能调用就代表它有权限。”注册是 capability exposure，不等于资源级 authorization。

`tools_condition` 是最小 ReAct 路由器

它只看最后 AIMessage 有没有 tool_calls。
builder.add_node("model", call_model)
builder.add_node("tools", ToolNode(tools))

builder.add_edge(START, "model")
builder.add_conditional_edges(
    "model",
    tools_condition,
)
builder.add_edge("tools", "model")
AIMessage has tool_calls
→
tools
→
model
AIMessage no tool_calls
→
END
它解决的是标准 Tool Loop。等你需要 approval、复杂 branching、显式 Plan 或多种停止条件时，就会开始超出一个 `tools_condition` 的表达能力。

`create_agent` 到底帮你省了什么？

现在再看高层 API，就不会觉得它是魔法。
High-level
from langchain.agents import create_agent

agent = create_agent(
    model=model,
    tools=tools,
)

标准 agent loop、messages state、tools node、middleware integration 已经给你搭好。

Custom Graph
StateGraph(...)
add_node("model", ...)
add_node("tools", ToolNode(...))
add_conditional_edges(...)
compile()

当你要自己决定 State、branch、interrupt、subgraph、fan-out 时，用更低层 Graph API。

8

真实模型和本课 deterministic model 的区别

本课故意不需要 API key，但框架路径是真实的。

项目里的 `deterministic_model_node()` 不“假装是 LLM”。它只是稳定地产生一个真实 `AIMessage(tool_calls=[...])`，目的是让测试能离线验证：

AIMessage.tool_calls
→
ToolNode
→
ToolMessage
→
tools_condition → END
以后换成真实 ChatModel 时，替换的是 model node 的“谁决定 tool_calls”，不是 ToolNode / ToolMessage / graph edge 这套协议。
